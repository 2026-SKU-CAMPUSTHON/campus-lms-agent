# 강의 기반 LMS 평가 계획

2026-10-26 · `1.0.0-candidate` · 준비 시점 코드 `c701a5f9b74337ecf56457af6a424e4af2122f8d`

**준비 이후 2026-10-26 실제 실행과 AI 잠정 채점을 완료했다.** [결과 보고서](results-2026-10-26.md)에서 퀴즈 30문항·Q&A 30×2 비교를 확인한다. AI가 원문을 바탕으로 작성한 정답 후보는 여전히 두 사람의 독립 검토 후 확정해야 한다. 영상은 자동 자막 기반이므로 원영상의 소리·화면 확인이 필요하다. 아래 계획의 사람 검토·기능·시간 단계는 미완료다.

- [평가 데이터](../../evaluation/v1/README.md): 질문·참고 정답·기대 경로·근거·기능 검사
- [읽기용 질문·정답 목록](../../evaluation/v1/reviewer-catalog.md): 검토자용 후보 전체

- [Excel 채점표](../../outputs/evaluation-20261026/campus-evaluation-scorecard.xlsx): 요약·정답검토·퀴즈채점·Q&A채점·기능테스트·시간비교, 6개 시트
- [자료·범위·해시](../../evaluation/v1/source-manifest.json)

Excel을 평가자별로 복사하고 독립 채점 후 불일치를 조정한 최종본을 만든다. 평가자 두 명을 표본 두 개로 세지 않는다. 노란 칸은 입력, 회색은 수식이다. Git의 원본 템플릿에는 실제 점수를 입력하지 않는다.

## 목적과 구성

교수에게 쓸 만한 퀴즈를 제공하는지, Q&A가 근거 있는 답변·추가 질문·교수 승격을 적절히 선택하는지, 업무 흐름·권한·레포트가 동작하는지 평가한다. 같은 품질에 도달하는 작업 시간도 비교한다. 참여율로 학생의 열정·진취도나 학습 효과를 단정하지 않는다.

| 세트 | 개수 | 용도 |
| --- | ---: | --- |
| 퀴즈 생성 | 3회 × 10문항 = 30문항 | 범위별 첫 생성 결과 평가 |
| 퀴즈 참고 기준 | 30개 | 검토용 개념 질문·정답; 실제 생성 출력 아님 |
| 최종 Q&A 후보 | 30개 | 답변 가능 10·모호 10·근거 부족 10 |
| 개발 Q&A | 6개 | 범주별 2개; 설정·실행 도구 점검 |
| 기능 검사 | 12개 | 교수 1명·학생 3명 역할 교대 |
| 시간 파일럿 | 팀원 4명 | 직접 5문항 작성과 AI 생성·검토 5문항 비교 |

모호한 질문 중 5개는 지정된 보완 응답 후 답할 수 있고, 5개는 계속 모호해 승격해야 한다. 명확한 근거 부족은 불필요한 보완 없이 승격한다. 추가 질문 문구의 완전 일치 대신 필요한 정보를 묻는지 평가한다.

## 원문과 주차 격리

| 범위 ID | 자료·범위 | 용도 |
| --- | --- | --- |
| PDF_DEV | `ch13_텍스트 마이닝.pdf` 5–11쪽 | 개발 |
| YT_DEV | 영상 12:12–13:52 | 개발 |
| PDF_MODEL | 같은 PDF 18–23쪽 | 최종 후보: 감성 분류 |
| PDF_TOPIC | 같은 PDF 44–59쪽 | 최종 후보: 토픽 모델링 |
| YT_CONCEPT | 같은 영상 20:00–28:10 | 최종 후보: 유한합·급수·푸리에 개념 |

영상: https://www.youtube.com/watch?v=XwsPTAnFRsk . **텍스트 마이닝이 아니라 공학수학 강의다.** PDF와 영상은 다른 테스트 강의로 만들고 범위마다 별도 주차로 격리한다. PDF 페이지는 파일의 물리적 순서 기준 1부터 시작하며 양 끝 포함이다. 영상은 시작 이상·끝 미만의 초 구간이고 경계 자막을 잘라 사용한다.

다른 범위·개발용 자료를 최종 질문의 근거로 쓰면 범위 위반이다. QA26·QA30은 이를 검사한다. 학생 원본 공개 여부와 AI 근거 사용 권한은 구분한다.

PDF는 60쪽이며 선정 페이지의 텍스트와 렌더링을 확인했다. 영상은 기존 저장된 한국어 자동 자막 601개 구간을 읽었다. 수학 용어 오인식과 겹치는 구간이 있어 모든 영상 정답에 `requires_video_review=true`를 붙였다. 원영상 검토 전 확정 정답으로 취급하지 않는다. 원본 PDF·전체 자막·영상은 저장소에 배포하지 않는다.

공개 저장소에 정답 후보가 있으므로 비공개 벤치마크나 모델 학습 자료와 독립된 데이터라고 주장하지 않는다. 개발에 사용하지 않는 운영상 분리만 가능하다. reviewer 파일·참고 정답을 생성 프롬프트, 검색 인덱스, 튜닝 에이전트에 전달하지 않는다.

PDF 2–60쪽은 이전 기능 검증에서 이미 생성 입력으로 사용했다([기록](../verification.md)). 따라서 이번 분리는 새 평가 질문과 개발 질문의 분리이며, 자료 자체가 미노출이었다는 뜻은 아니다.

## 실행 순서

1. 두 사람이 원문과 정답 후보를 독립 검토한다. 영상은 지정 구간의 소리·화면을 확인한다. 질문·정답·경로·페이지/시간을 수정하고 불일치를 조정한다.
2. 세트 버전, 각 파일 SHA-256, 검토자, 날짜를 기록하고 고정한다. 승인 없이 `candidate`를 검증 완료로 바꾸지 않는다. 실제 실행 코드 커밋은 준비 시점 코드와 별도로 기록한다.
3. 개발용 6개로 주차 격리·로그·채점 방식을 연습한다. 최종 질문을 본 뒤 프롬프트를 고치면 그 실행은 개발 결과로 표시하고 새 최종 세트를 준비한다.
4. 범위별 퀴즈 10문항을 한 번 요청한다. 첫 결과·실패·누락·중복을 그대로 남긴다. QR 참고 질문과 같을 필요는 없고 같은 범위의 다른 올바른 개념도 허용한다.
5. Q&A 두 조건에 동일한 초기 질문 30개를 실행한다. 각 사례는 새 대화로 시작한다. 추가 질문을 요청한 경우에만 준비된 학생 응답을 한 번 전달한다. 두 조건 순서는 사례별로 교차한다.
6. 실제 답변·검색 근거·판단·경로·시간·오류를 저장한다. API 오류를 정당한 승격이나 정답으로 세지 않는다. 가능하면 평가자에게 조건 이름을 가린다.
7. 교수 1명·학생 3명으로 기능 검사를 수행한다. 장애 주입·컨테이너 교체·복구 검사는 폐기 가능한 환경에서만 한다.
8. 독립 채점의 불일치를 조정하고 전체 결과를 집계한다. 재시도는 새 run ID로 남겨 최초 결과를 덮어쓰지 않는다. 수정 전·후 결과를 구분한다.

## Jev 비교

| 조건 | 동작 |
| --- | --- |
| direct_answer | 같은 검색·Claude 설정을 사용하되 Jev 사전 판단과 자동 보완 질문을 적용하지 않는다. 출처 없는 답변의 기존 승격 규칙은 유지한다. |
| jev_gate | 현재 Jev 명확성·근거 판단, 신뢰도 기준 0.75, 보완 질문 최대 1회, 교수 승격을 사용한다. |

자료 스냅샷, 검색 수·설정, 모델의 정확한 ID·파라미터, 답변 프롬프트, 코드 버전을 고정한다. 현재 검색은 최대 6개이며 실행 시 실제 설정을 기록한다. [비교 실행기](../../scripts/evaluation/README.md)를 별도 평가 환경에서 구현·실행했다. 이 비교는 Jev를 포함한 분기 흐름 전체의 효과이며 Jev 모델만의 순수 효과라고 해석하지 않는다.

현재 정책은 판단 신뢰도 부족 시 승격, 모호한 첫 질문에는 보완, 두 번째에도 모호하면 승격, 근거 부족이면 즉시 승격이다. 생성 답변에 유효한 출처가 없을 때도 승격한다. 전체 지정 자료에는 답이 있지만 검색 결과에는 없다면 검색 실패와 판단 실패를 분리한다. Jev 출력 신뢰도를 실측 정확도로 보고하지 않는다.

## 기록과 역할

실행 결과는 `.data/evaluation-runs/<run_id>/`에 저장한다. 예: `20261028_jev_gate_01`. 데이터 버전·해시, 코드 커밋, 원문 해시, 모델 설정, 조건, scope/case ID, 검색 근거, 원응답, 실제 경로, 보완 횟수, API 상태·사용량·비용 단위, 지연 시간, 평가자 점수를 기록한다. 비용을 모르면 빈칸이며 0원으로 쓰지 않는다.

가상 계정을 사용하고 원문·전체 자막·응답 전문·계정·키·쿠키는 공개 저장소에 올리지 않는다. 채점본은 접근을 제한하며 공개 결과는 익명 집계와 필요한 짧은 사례만 포함한다.

| 날짜 | 작업 | 역할 제안 |
| --- | --- | --- |
| 10/26 | 후보 정답·영상 확인 | B·C 독립 검토, A 불일치 조정 |
| 10/27 | 세트 확정·해시, 개발용 연습, 비교 실행기 | A 실행·통계, D Q&A 기록·비교 구현 |
| 10/28 | 퀴즈·Q&A 두 조건 실행, 독립 채점 | A 실행, B·C 채점, D 실패 원인 분류 |
| 10/29 | 기능 검사·시간 파일럿, 중대 결함 수정 | 전원; 개발자가 자신의 결과를 단독 승인하지 않음 |
| 10/30 | 채점 조정·재검사·발표 결과표 | 전원 |
| 10/31 | 최종 시연·제출 | A 통합, 역할별 확인 |

AI는 로그 정리·초벌 점검에 사용하고 최종 판정은 사람이 원문을 확인한다. 일정은 제안이며 실행 완료를 뜻하지 않는다. 네 명의 시간·사용성 결과는 내부 파일럿이며 교수·학생 집단으로 일반화하지 않는다. 이슈 #6은 리허설·최종 제출까지 열린 상태로 유지한다.

**남은 일:** 사람 정답 승인·독립 채점, 원영상 검증, 기능 검사·시간 측정. 실제 모델 실행과 AI 초벌 채점은 결과 보고서에 기록했다. 후보 세트의 잠정 점수를 사람 검증 성능으로 발표하지 않는다.
