# 4명과 각자의 AI가 협업하는 방법

공유 기준은 이 저장소의 계약, 이슈, PR이다. GitHub에 글을 쓰면 다른 AI가 자동으로 실행되지는 않는다. 각 AI에는 저장소 조회와 필요한 이슈·PR 작성 권한이 있어야 한다.

1. 사람은 A~D 역할과 GitHub 계정을 배정한다. 현재 담당 계정은 미정이다.
2. AI는 `AGENTS.md`, 자신의 이슈, 선행 이슈, 공용 계약을 읽고 담당과 `in_progress`를 기록한다.
3. 의존 API가 없으면 합의된 샘플로 구현한다. 계약 변경은 영향 받는 담당에게 이슈로 전달하고 A가 통합한다.
4. 검증 후 PR을 열어 `review`를 기록한다. 다음 담당은 관련 이슈와 PR을 읽고 연동한다.
5. 병합과 완료 기준 확인 후 `done`으로 기록한다. 차단되면 원인·필요 결정·다음 담당을 남기고 독립 작업을 이어간다.

인계 메시지에는 작업 이슈, 담당, 상태, 계약 버전, 변경 요약, 실제 검증 결과, 관련 PR, 다음 담당의 조치를 포함한다. 토큰·키·원본 학생 자료는 인계에 넣지 않는다.

## 각 AI에게 줄 첫 프롬프트

```text
저장소: https://github.com/2026-sku-campusthon/campus-lms-agent
내 역할: [A/B/C/D]
담당 이슈: [실제 이슈 번호]
AGENTS.md와 담당 이슈, 선행 이슈, docs/contracts를 읽고 개발해줘.
시작 시 담당·상태를 이슈에 기록하고 작업별 브랜치를 사용해줘.
계약 변경은 영향과 샘플을 공유하고 A가 통합하도록 해줘.
실제 검증 결과와 다음 담당의 할 일을 PR·이슈에 남겨줘.
```

AI가 별도 채팅에서 일하더라도 이슈·계약이 공통이면 협업할 수 있다. 자동 실행·실시간 메시지 버스·다른 사람 계정의 연결 설정은 이 초기 저장소에 포함하지 않았다.
