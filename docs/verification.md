- 교수 게시: 생성한 문항 중 **5개 선택 게시**.

### 실제 퀴즈

`node --import tsx scripts/verify-live-flow.ts <실제 강의 PDF> 3 2 15`로 물리 페이지 2~15를 추출하고 Claude가 **3문항 생성**, 교수 **3개 게시**, 학생 답안 **1정답·2오답**과 풀이를 확인했다. 제출 전 정답 비노출도 검사했다. Claude로 50문항을 호출한 결과는 아니며 앞의 50문항은 이전 Codex 결과다.

### 실제 Q&A

`node --import tsx scripts/verify-live-qa.ts`는 등록된 실제 강의 자료를 읽고 임시 DB에서 실제 Jev·Claude·HTTP 라우트를 사용했다.

- IDF 의미 질문: `resolved`, 보완 질문 0회, 강의 **8페이지** 출처 답변.
- 모호한 질문: 보완 질문 **1회**, 여전히 모호한 학생 답변 후 `awaiting_professor`·`unclear_after_clarification`, 교수 직접 답변 후 `resolved`.
- 자료 밖의 화성 기온 질문: `awaiting_professor`·`judgment_uncertain`, 보완 질문 0회. 이 경로는 판단 불확실 승격이다. 이를 근거 부족 분기의 성공이나 명확성 판단 정확도로 해석하지 않는다.

메타데이터만 `.data/live-qa-verification.json`에 남겼고 임시 DB는 삭제했다. 원문·대화·생성 본문·비밀키는 검증 로그나 커밋에 포함하지 않았다. 실제 한국어 사례 3개의 분기 확인이며 통계적 정확도나 임계값 보정 완료를 뜻하지 않는다.

## 교수 레포트 검증 (API 0.4.0-reports.1)

교수 레포트는 저장된 제출·대화만 읽으며 모델을 호출하지 않는다. 서버 검사 6개를 추가해 전체 **28개**, Python **2개**, 브라우저 **3개**가 통과했다. TypeScript·빌드·OpenAPI 및 합성 보고서 샘플 검사도 통과했다.

- 같은 학생의 여러 퀴즈·주차 제출을 한 명으로 세고, 중복 요청 키로 같은 제출이 다시 집계되지 않는지 검사했다.
- 1주차 3/5 정답·2주차 0/1 정답의 전체를 3/6=50%로 계산했다. 주차 비율의 단순 평균 30%와 구분했다.
- 미게시·미제출·학생 0명은 null 표시 조건을 확인하고, 실제 모두 오답인 0%와 구분했다. 수강생 변경 시 현재 membership 기준으로 분모·제출 대상을 일치시켰다.
- 학생·비로그인·다른 강의 교수 접근을 거부했다. 주차 UUID 중복·빈 필터·잘못된 페이지·다른 강의 주차를 검사했다.
- Q&A 106개를 합성 저장해 페이지 밖의 대화도 전체 집계에 포함하는지 확인했다. 목록의 내부 판단·학생 UUID 비노출과 오류/현재 상태의 중복 집계도 검사했다. 보고서 조회 중 Judge 호출은 0회였다.
- 브라우저에서 2주차 선택, 참여율 50%·정답률 50%, 문항별 100%·0%, Q&A 대화 펼치기, 전체 선택 해제와 학생의 탭·API 접근 차단을 확인했다. 데스크톱·390px 모바일의 문서 가로 넘침 검사를 통과했다. 표는 좁은 화면에서 표 영역만 가로 스크롤한다.

실행 중인 실제 로컬 서버의 기존 저장 자료도 별도로 대조했다. 게시 퀴즈 2개·8문항, 현재 학생 2명 중 제출 학생 1명, 제출 2건·정답 2/8이었다. API의 **참여율 50%·정답률 25%**가 별도 SQL의 COUNT DISTINCT/SUM과 일치했다. 당시 실제 저장 Q&A는 0건으로 API도 0건이었다. Q&A 다건·대화 표시 검증은 합성 자료를 사용했으며 운영 DB에 시연용 대화를 추가하지 않았다.

수강 이력 스냅샷, 보고서 파일 다운로드, Supabase·RLS·실서비스 배포는 이번에 검증하지 않았다. 현재 집계 규칙은 docs/reports.md에 명시했다.

`npm run typecheck`, `npm test`(서버 **36개**·Python **7개**), `npm run build`, `npm run test:e2e`(**4개**), `.venv-worker/bin/python scripts/check_contracts.py`, `git diff --check`가 통과했다. 시스템 Python에는 계약 검사 의존성이 없어 처음 실행이 실패했으며, requirements-contracts.txt를 가상 환경에 설치한 뒤 계약 검사를 통과했다.

### 실제 모델·한국어 음성 샘플

- 브라우저: 2주차 선택·PDF 파일 다운로드와 내용/파일명, 현재 선택 주차 전달, 주차 미선택 비활성, 생성 오류 안내 후 재시도, 390px 가로 넘침을 확인했다. 기존 퀴즈/Q&A/전사 검사를 함께 통과했다.

### 실제 로컬 레포트

실제 실행 중인 사이트의 교수 화면에서 **1주차만 선택해 PDF 다운로드**를 수행했다. 기존 PDF 퀴즈 8문항과 실제 YouTube 퀴즈 5문항을 포함한 **게시 퀴즈 3개·13문항·참여율 50%(1/2명)·정답률 38.5%(5/13개)**, 실제 Q&A **2건·답변 완료 2건·추가 질문 사용 1건·교수 답변**이 들어간 A4 **7쪽·153,137bytes** PDF를 확인했다. 두 번째 주차와 화면의 페이지 제한을 섞지 않는다.

Poppler로 7쪽을 PNG로 렌더링하고 전체 페이지 시트 및 첫 장/수식/대화 페이지를 확인했다. 초기 Nanum Gothic에 없던 π가 코드로 표시되는 문제는 DejaVu Sans 보조 글꼴을 동봉해 실제 수식과 PDF 추출에서 정상 π로 확인했다. 페이지 번호·머리글·표·줄바꿈·정답/풀이·영상 시간 출처와 교수 답변도 확인했다. 실제 강의 문제/대화/파일은 .data/verification-report-pdf에만 저장하며 커밋하지 않는다.

PDF는 저장된 결과를 읽고 만들었으며 새 문항·제출·대화·모델 호출을 만들지 않았다. 실제 사용자에게 파일을 제공하되 장기 서버 저장/공유 링크·AI 서술형 요약·Supabase/실서비스 배포는 이번 범위가 아니다.


## 학생 개인 오답 PDF 검증 (2026-10-22, API 0.10.0-student-report.1)

### 실제 저장된 학생 결과

실제 사이트의 학생 가 계정으로 1주차만 골라 **오답 PDF 다운로드**를 수행했다. 기존 문서와 실제 YouTube를 합친 제출 **3건·13문항·정답 5개·오답 8개·정답률 38.5%** 요약과 본인의 오답 8개·내 선택·정답·풀이·문서 페이지/영상 시간 출처를 포함한 A4 **5쪽** 파일이다. 저장된 제출과 PDF 추출 텍스트를 대조해 오답/풀이가 전부 들어가고 맞힌 문항 텍스트가 제외됨을 확인했다. YouTube의 비공개 출처는 원본 URL 없이 시각과 비공개 표시만 담았다.
