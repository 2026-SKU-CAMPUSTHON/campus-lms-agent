2026-10-21, 로컬 개발 환경에서 수행했다. GitHub Actions 결과와 구분한다.

- `npm run build`: Express 실행 파일과 Vite 정적 파일 생성 통과.
- `scripts/check_contracts.py`: OpenAPI·Worker 샘플·학생 응답 정답 비노출·Figma SVG 체크섬 통과.
- `npm audit --audit-level=high`: 확인 시점 알려진 취약점 0개.
- 실제 60페이지 한국어 강의 PDF에서 2~15페이지 텍스트·원래 페이지 번호 추출 확인.
- 실제 같은 PDF로 퀴즈 Playwright 브라우저 검사 통과: 교수 업로드·3문항 초안·2문항 선택 게시·학생 제출·오답·새로고침·다른 학생 격리·390px 모바일 가로 넘침 검사. **이 검사에서 생성 응답은 테스트 대역이다.**
- 기존 ChatGPT 로그인으로 Codex CLI를 호출해 실제 강의 PDF에서 객관식 문제·정답·풀이·페이지 출처 1개 생성 확인. 결과의 형식과 출처 범위를 검사했다.

## 서버 검사 범위

선택 범위 준수, 일부 문항만 게시, 제출 전 정답·풀이 비노출, 비공개 원본·교수 초안 접근 거부, 학생·강의 간 접근 제어, 개인 결과 격리, 서버 채점, 같은 제출 키 재전송, 1회 제출 제한, 로그아웃, 외부 Origin 거부, 재시작 후 결과 보존, 자료 범위 초과, 키 누락, 모델 오류, 범위 밖 출처 거부, 테스트 대역으로 50문항 배치 생성.

## 실제 50문항 검증

사용자가 제공한 60페이지 한국어 강의 PDF의 **2~60페이지**로 실제 Codex를 호출했다. 테스트 대역을 사용하지 않았다.

- 생성: **50문항**, 보기·정답·풀이·페이지 출처 검증 통과.
- 교수 게시: 생성한 문항 중 **5개 선택 게시**.
- 학생 조회: 게시된 **5문항만 반환**, 정답·풀이 비노출 확인.
- 서버 채점: 검증용 답안을 제출해 **1개 정답·4개 오답**, 기대값과 일치.
- 학생 결과: 오답 4개와 정답·풀이 확인.

검증은 `node --import tsx scripts/verify-live-flow.ts <로컬 자료 경로> 50 2 60`으로 수행했다. 원본 PDF와 생성 결과는 로컬 `.data/`에만 남겼다. 생성 문항·원본 강의 PDF·로그인 정보는 저장소에 올리지 않았다. 50개 문항 전체의 내용상 정확성·난이도를 교수 검토로 평가한 결과는 아니다.

## 남은 검증

OpenAI API는 키 인증·모델 접근을 확인했지만 실제 생성은 잔액 부족(`credit_balance_exhausted`)으로 완료하지 못했다. Supabase·JWT·Storage·RLS, 한국어 Jev 확대 평가, 레포트, 실제 서비스 배포는 아직 검증하지 않았다. 모델 출력 구조·출처 검증은 내용상 정답을 보증하지 않는다.

## Q&A 초기 검증 (Claude 전환 전)

같은 날 Q&A를 추가하고 TypeScript·빌드·계약 검사를 다시 수행했다. 서버 검사는 기존 5개와 Q&A 12개로 총 17개다. Python 추출 2개, Playwright 브라우저 2개(퀴즈·Q&A)가 통과했다.

- 서버: 근거 있는 답변·출처, 보완 질문 1회, 학생 답변 후 재검색·재판단, 여전히 모호하거나 근거가 부족한 질문의 승격, 교수 답변, 중복 요청·오래된 버전 거부, 다른 학생·강의 격리, 교수만 판단 기록 조회.
- 실패: Jev 키 누락은 오류이며 승격하지 않음, 생성 실패 뒤 재시도해도 질문 횟수 중복 없음, 불확실한 판단·출처 없는 답변의 승격, 대화·추가 질문 횟수의 재시작 보존.
- 검색: 다른 강의·주차·미완료 자료와 교수 선택 범위 밖 페이지를 제외한다. 원본 비공개 자료도 허용된 AI 처리에는 사용한다.
- SDK: 실제 `@typesafe-ai/sdk`에 HTTP 테스트 대역을 주입하여 버전·두 choice·확률 파싱과 인증 실패 처리를 확인했다. 외부 Jev 호출은 아니다.
- 브라우저: 학생의 모호한 질문, 추가 질문 1회, 학생 보완, 교수 승격, 교수 답변, 학생의 완료 확인, 다른 학생 격리와 390px 가로 넘침 검사를 통과했다. 이 검사의 Jev 판단·생성 응답은 모두 명시적인 테스트 대역이다.

실제 강의 PDF를 대상으로 로컬 검색 결과 6개를 전달하여 **실제 Codex CLI**로 381자 답변과 27자 보완 질문 문장을 생성했다. 답변 출처는 물리 페이지 7·8이었고 검색 근거와 일치했다. 이 검증은 Jev 판단을 호출하지 않고 생성 모듈을 직접 확인했다. 원본 문서와 생성한 본문은 커밋하지 않았다.

초기 연결 당시 로컬 실행 서버의 `/api/health`는 `contract_version=0.3.0-qa.1`, `provider=codex`, `jev_configured=false`, `qa_configured=false`를 반환했다. 당시에는 TypeSafe 키가 없어 전체 실제 Q&A 모델 연결을 검증하지 못했다. 이후 실제 연결 결과는 아래에 기록한다. 한국어 판단 정확도·임계값은 확대 평가가 필요하다. `jev-1.13.0`과 0.75 임계값을 검증 완료값으로 해석하지 않는다.

## Claude API·실제 Jev 연결 검증

2026-10-21 사용자 요청으로 기본 생성을 `claude-sonnet-5-5`로 전환했다. API 계약은 `0.3.1-claude.1`이다. 다음 검증에서 Claude와 Jev는 테스트 대역이 아닌 실제 외부 API다.

### 실제 퀴즈

`node --import tsx scripts/verify-live-flow.ts <실제 강의 PDF> 3 2 15`로 물리 페이지 2~15를 추출하고 Claude가 **3문항 생성**, 교수 **3개 게시**, 학생 답안 **1정답·2오답**과 풀이를 확인했다. 제출 전 정답 비노출도 검사했다. Claude로 50문항을 호출한 결과는 아니며 앞의 50문항은 이전 Codex 결과다.

### 실제 Q&A

`node --import tsx scripts/verify-live-qa.ts`는 등록된 실제 강의 자료를 읽고 임시 DB에서 실제 Jev·Claude·HTTP 라우트를 사용했다.

- IDF 의미 질문: `resolved`, 보완 질문 0회, 강의 **8페이지** 출처 답변.
- 모호한 질문: 보완 질문 **1회**, 여전히 모호한 학생 답변 후 `awaiting_professor`·`unclear_after_clarification`, 교수 직접 답변 후 `resolved`.
- 자료 밖의 화성 기온 질문: `awaiting_professor`·`judgment_uncertain`, 보완 질문 0회. 이 경로는 판단 불확실 승격이다. 이를 근거 부족 분기의 성공이나 명확성 판단 정확도로 해석하지 않는다.

메타데이터만 `.data/live-qa-verification.json`에 남겼고 임시 DB는 삭제했다. 원문·대화·생성 본문·비밀키는 검증 로그나 커밋에 포함하지 않았다. 실제 한국어 사례 3개의 분기 확인이며 통계적 정확도나 임계값 보정 완료를 뜻하지 않는다.

### 자동 검사·실행 설정

기존 검사와 Claude SDK 검사를 합쳐 서버 **22개**, Python **2개**, Playwright **2개**, TypeScript·빌드·계약 검사가 통과했다. Claude SDK 검사는 구조화 출력, 범위 밖 출처, 잘린 응답·거절, 키 누락·인증·한도 오류, 원문 비노출·자동 재시도 금지를 HTTP 테스트 대역으로 확인했다. 브라우저 자동 검사 역시 테스트 대역이며 실제 모델 검증과 구분한다.

실행 중인 로컬 서버를 다시 시작하여 `/api/health`의 `provider=claude`, `model=claude-sonnet-5-5`, `qa_configured=true`, `jev_configured=true`를 확인했다. 키 존재만으로 잔액을 검증하는 API는 아니며 앞의 실제 호출 결과로 연결을 확인했다.

## 교수 레포트 검증 (API 0.4.0-reports.1)

교수 레포트는 저장된 제출·대화만 읽으며 모델을 호출하지 않는다. 서버 검사 6개를 추가해 전체 **28개**, Python **2개**, 브라우저 **3개**가 통과했다. TypeScript·빌드·OpenAPI 및 합성 보고서 샘플 검사도 통과했다.

- 같은 학생의 여러 퀴즈·주차 제출을 한 명으로 세고, 중복 요청 키로 같은 제출이 다시 집계되지 않는지 검사했다.
- 1주차 3/5 정답·2주차 0/1 정답의 전체를 3/6=50%로 계산했다. 주차 비율의 단순 평균 30%와 구분했다.
- 미게시·미제출·학생 0명은 null 표시 조건을 확인하고, 실제 모두 오답인 0%와 구분했다. 수강생 변경 시 현재 membership 기준으로 분모·제출 대상을 일치시켰다.
- 학생·비로그인·다른 강의 교수 접근을 거부했다. 주차 UUID 중복·빈 필터·잘못된 페이지·다른 강의 주차를 검사했다.
- Q&A 106개를 합성 저장해 페이지 밖의 대화도 전체 집계에 포함하는지 확인했다. 목록의 내부 판단·학생 UUID 비노출과 오류/현재 상태의 중복 집계도 검사했다. 보고서 조회 중 Judge 호출은 0회였다.
- 브라우저에서 2주차 선택, 참여율 50%·정답률 50%, 문항별 100%·0%, Q&A 대화 펼치기, 전체 선택 해제와 학생의 탭·API 접근 차단을 확인했다. 데스크톱·390px 모바일의 문서 가로 넘침 검사를 통과했다. 표는 좁은 화면에서 표 영역만 가로 스크롤한다.

실행 중인 실제 로컬 서버의 기존 저장 자료도 별도로 대조했다. 게시 퀴즈 2개·8문항, 현재 학생 2명 중 제출 학생 1명, 제출 2건·정답 2/8이었다. API의 **참여율 50%·정답률 25%**가 별도 SQL의 COUNT DISTINCT/SUM과 일치했다. 당시 실제 저장 Q&A는 0건으로 API도 0건이었다. Q&A 다건·대화 표시 검증은 합성 자료를 사용했으며 운영 DB에 시연용 대화를 추가하지 않았다.

수강 이력 스냅샷, 보고서 파일 다운로드, Supabase·RLS·실서비스 배포는 이번에 검증하지 않았다. 현재 집계 규칙은 docs/reports.md에 명시했다.

### 브라우저 검사 환경 보완

레포트 첫 커밋의 PR 검사는 통과했으나 push 검사에서 기존 Q&A 테스트가 스크린샷 다음 로그아웃 클릭을 기다리다 60초 제한에 도달했다. 앱과 무관한 외부 폰트 CDN 요청을 공유 Playwright fixture에서 차단하여 검사 환경의 외부 통신 의존을 줄였다. 제품의 글꼴 설정은 변경하지 않는다. 원래 실패 로그만으로 특정 원인을 단정하지 않는다. 보완 후 전체 브라우저 검사 3개가 다시 통과했다.
